# Native parity screen capture matrix

This matrix keeps every in-scope route visible until Step 1 captures and records it. “Observed” means inspected in a browser session, not an approved or checked-in screenshot. Native source implementation may proceed where the plan allows foundation/API parity, but it does not count as visual or journey sign-off.

Authenticated customer states require approved non-production test data. No such account was available for this capture session, and no production account or transaction was used; authenticated route states remain pending rather than being represented with fabricated content.

The active website and parallel mobile locale configs currently enable only `en` and `my`; other translation directories are not active locale routes. The port plan's reference to five currently configured locales needs product/operations reconciliation before locale sign-off.

## Required capture notes per route

- Record the viewport dimensions, system font scale, locale, and whether the user is signed in (use only approved non-production test data).
- Record navigation destinations, form rules, exact visible copy and localization keys, links, dialogs, sheets, and bottom-navigation state.
- Capture each relevant loading, empty, validation, error/offline, and success state. Mark a state N/A only after reviewing the source and confirming it cannot occur on that screen.
- Do not submit a bet, deposit, withdrawal, prize spin, legal acceptance, or other live transaction while collecting reference evidence.
- Preserve screenshot files only after they contain no personal data, credentials, account balances, or payment details.
